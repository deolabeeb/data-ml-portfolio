SupportOps Agent

Verified local mock · M1

A local deterministic support workflow with typed LangGraph routing, customer-owned persistent conversations and bounded execution.

The problem and current scope

Support conversations need reliable answers without exposing another customer's orders or carrying their context into the wrong account. SupportOps demonstrates that boundary using synthetic customers and orders: an authenticated local workflow answers authorized requests, resumes owner-owned conversations and fails explicitly when execution cannot safely continue. No real customer outcome or deployed service is claimed.

Solution — accepted local M1 behaviour

A server-established customer identity controls order lookup and conversation access. Typed LangGraph routing selects order status, fixture-backed policy answers, review drafts, clarification or abstention. Refund/cancellation text is an unsaved draft, not an executed action. Order references carried between turns are reauthorized on each use; foreign and unknown conversation IDs receive the same non-revealing denial.

Architecture — identity, graph and atomic memory

FastAPI authentication establishes the principal before owner-filtered conversation admission. A scoped SQLite checkpoint saver guards every memory access. The typed graph follows route → selected operation → finish; runtime identity and execution budgets remain outside persisted state. A whole turn commits checkpoint and turn count atomically, or rolls back together on failure. Independent TestClient processes reopened the same SQLite database and continued an authorized conversation; this was not a live browser/server restart.

Failure handling — bounded waiting, not forced cancellation

M1 server policy allows 8 graph steps, 6 operation requests, 4 read-tool calls, 2 seconds per operation and 20 seconds per turn, with zero retries/model calls. Explicit limit, timeout and capacity outcomes terminate the caller path; failed turns roll back and can recover. Four read-only worker slots include timed-out workers until they exit, and late results cannot advance conversation memory. Caller waiting is bounded; arbitrary blocking Python and filesystem work are not forcibly stopped.

Evidence — milestone-labelled local runs

Recorded on 1 October 2026, Windows 10 X64 / CPython 3.12.14 with synthetic fixtures: S00/M0 39 tests plus 14 loopback checks; S01 35 routing cases / 74 total; S02 33 persistence cases / 107 total; S03/M1 27 execution cases / 134 total. Counts overlap across milestones and must not be added. S03's scripted CLI demonstration covered successful follow-up, foreign-customer denial, step-limit failure and recovery. These are saved milestone results, not P01 application reruns, benchmarks or remote CI.
